Задание 3 · Форма покупки билетов

Вариант A: проверка на лету, предпросмотр, итоговый билет.

Что требовалось

  • ≥6 полей и 4 правила, которые атрибутами HTML не выразить
  • Живой предпросмотр на каждом input
  • Нет ошибок при загрузке; проверка на blur, потом на каждый ввод; aria-invalid
  • Отправка: число ошибок сверху и фокус на первом; успех: результат через DOM и сброс формы
  • form.noValidate = true, клавиатура

Что мы сделали

  • 7 полей, 6 своих правил (дата из списка, не sold out, места, имя из 2 слов, почта, промокод)
  • Билет со случайным кодом, места уменьшаются после покупки

Вопросы на защите

Зачем noValidate?
Отключает всплывающие подсказки браузера, чтобы показывать свои. checkValidity() продолжает работать.
Когда проверяется поле?
Первый раз при blur, далее на каждом input (флаг dataset.touched).
Зачем setCustomValidity?
Чтобы полe было «неверным» и для API браузера, а не только на вид.
